# 用 PARA 整理了 500 条笔记，我的改变是……

副标题：一个写 Bug 的后端，终于不再被自己的知识库吓到

我是阿木木，一个写后端代码、也常写 Bug 的普通人。

在用 PARA 之前，我的笔记大概是这样的：

  * 各种软件：飞书云文档、印象笔记、Bear、备忘录、微信收藏、浏览器书签……
  * 各种命名：未命名-1、新建文本文档(2)、方案-最终版-确定-v3
  * 各种心态： 看到好文章：先收藏，心想“以后系统地学一下” 想写点东西：打开一堆标签页，发现什么都想讲，又什么都讲不清



某天我在 Obsidian 里看统计，吓了一跳：

> 笔记条数已经接近 **500** 。  
> 但我真正能随手调用、复用的，大概不到 50 条。

那一刻我意识到，我不是没有“记笔记”，  
而是——**我的笔记在反过来“记住了我”，把我困住了。**

后来我开始尝试用 PARA（Projects / Areas / Resources / Archives）  
去重新整理这 500 条笔记。

这篇文章就想认真回答标题那句话：

> 用 PARA 整理了 500 条笔记，我的改变到底是什么？  
> 而不是再给你讲一遍「什么是 PARA」。

我会讲 3 件事：

  1. 我是怎么在 Obsidian 里，实际落地 PARA 的
  2. 在整理完这 500 条笔记后，我的 3 个具体变化
  3. 如果你现在也有一堆乱糟糟的笔记，可以怎么用一个“最小 PARA” 起步



## 一、在 PARA 之前：我以为自己只是不够自律

先给你看一下「整理前」的几个典型场景，看你中不中：

### 1.1 想写一篇文章，却被自己的笔记吓退

比如我想写一篇「如何用 AI 辅助 Obsidian」的文章：

  * 搜索一下关键词，弹出几十条相关笔记： 某篇英文教程的摘录 某次 ChatGPT 对话剪贴 某个插件的配置笔记 零碎的“以后可以写写这个”的想法



我清楚地知道：

> 这些信息「都很有用」，  
> 但我完全不知道该从哪一条开始。

于是我做了件更简单的事——关掉 Obsidian，刷视频。

### 1.2 学完就忘：笔记越多，心里越虚

我有很多「学完了」的痕迹：

  * 某门课程的十几条笔记
  * 某本书的逐章摘录
  * 某个框架官方文档的要点记录



但每当同事问我：

> 「你之前不是学过 XXX 吗？你怎么看？」

我脑子里只有一个模糊印象：  
**“好像记在某个地方了，我回头翻翻。”**

问题是——大多数时候「回头」是不会发生的。

### 1.3 我以为自己只是“不够用心”

那时候我的解释是：

  * 我就是不够自律
  * 我就是没认真整理
  * 我就是不够聪明，记不住那么多东西



直到我接触到 PARA 这个思路，才隐约意识到：

> 也许不是我不行，  
> 是我一直在用「错误的结构」，来收纳「正确的内容」。

## 二、我眼里的 PARA：不是概念，而是 4 个「抽屉」

网上讲 PARA 的文章已经很多了，我只说我用起来之后的理解。

Tiago Forte 提出的 PARA，本质就是四个大抽屉：

  * P – Projects：项目 有明确目标、有截止时间的事情 比如：写一篇文章、做一个需求、准备一次分享
  * A – Areas：领域/职责 持续进行、没有明确结束时间 比如：职业发展、健康、理财、学习某个方向
  * R – Resources：资源 将来可能用到的参考资料 比如：教程、案例、好文章、别人的经验
  * A – Archives：归档 暂时不用，但也不想删掉 比如：已完成的项目、过期的方案



对我这个写后端的来说，它像什么呢？

  * Projects：像一个个「需求单」「任务 ticket」
  * Areas：像「负责的模块/服务」
  * Resources：像「技术栈文档、案例仓库」
  * Archives：像「归档的需求单、历史版本记录」



**重要的是：所有内容都归到「离行动最近的那一层」。**

> 你不是在分类知识，  
> 你是在分类「我要对这些东西做什么」。

## 三、我在 Obsidian 里落地 PARA 的方式（500 条笔记怎么迁）

### 3.1 我的 PARA 目录真实长这样

整理之后，我的 Obsidian 顶层变成了这个样子：

text
    
    
    📁 01_Projects    # 当前在执行的项目  
    📁 02_Areas       # 持续关注的领域/职责  
    📁 03_Resources   # 将来可能用到的资料  
    📁 04_Archives    # 已完成/暂时不用的东西  
    📁 99_Templates   # 模板  
    

`

几个例子：

**01_Projects**

text
    
    
    📁 01_Projects  
        📁 Write_IP_公众号文章  
            📝 2024-用PARA整理500条笔记  
            📝 2024-线上事故复盘  
        📁 Work_支付幂等性改造  
        📁 Learn_LLM_入门项目  
    

`

**02_Areas**

text
    
    
    📁 02_Areas  
        📝 Area_职业发展  
        📝 Area_身体健康  
        📝 Area_个人品牌/IP  
        📝 Area_工程实践（代码质量/测试/运维）  
    

`

**03_Resources**

text
    
    
    📁 03_Resources  
        📁 Obsidian_使用技巧  
        📁 PARA_相关资料  
        📁 AI_提示词&工作流  
        📁 Backend_架构文章  
    

`

**04_Archives**

text
    
    
    📁 04_Archives  
        📁 Projects_Completed  
        📁 Old_Notes_Import  
    

`

### 3.2 500 条旧笔记，我是怎么迁的？

老实说，一次性把 500 条笔记全部重分类，是不现实的。  
我最后采用了一个 **「先粗分，再细分」** 的策略：

#### 第一步：全部丢进「待整理」

我建了一个文件夹：`04_Archives/Old_Notes_Import`，  
把所有历史笔记先**全集合** 在这里。

> 这一步看似“退步”，  
> 但它有一个心理上的好处：  
> ——你终于知道「乱七八糟的东西都在这里」，  
> 而不是散落在整个库里。

#### 第二步：只整理「最近 1 个月实际用过的」

我给自己定了一个规则：

> 优先整理过去 30 天内用过 / 打开过的笔记。

在 Log / 搜索记录里找到这些笔记，一条条判定：

  * 如果它服务于一个正在进行的项目 → 放到 01_Projects 对应项目下
  * 如果它是某个长期关注的领域的关键思考 → 放到 02_Areas
  * 如果只是未来可能用到的参考 → 放到 03_Resources
  * 如果已经过期，但可以留作记录 → 留在 04_Archives



#### 第三步：整理时不纠结，只问一个问题

我发现自己以前整理笔记最大的敌人是——**纠结** 。

  * 这个放 Projects 还是放 Resources？
  * 这个笔记是不是应该拆成两条？
  * 这个东西以后会不会用到？



后来我只给自己留了一个判断问题：

> 「**未来 1 个月内，我会不会主动用到它？** 」

  * 会 → Projects 或 Areas
  * 不一定会，但可能用到 → Resources
  * 几乎不会 → Archives



至于「它属于哪个领域」「它和谁关系最近」，  
可以等用到的时候再调整。

#### 第四步：请 AI 帮我「快速给标签 & 归类建议」

有一些特别长的笔记（比如某门课程的长笔记），  
我会丢给 AI，让它先帮我判断适合放哪：

text
    
    
    这是我在 Obsidian 里的一条长笔记，内容是：  
      
    {粘贴要点或前半部分}  
      
    请你帮我判断：  
    1. 这条笔记更适合作为：  
       - 某个具体项目的素材，还是  
       - 某个长期关注领域的总结，还是  
       - 纯资料型内容？  
    2. 如果我要用 PARA 来分类，你建议放在 P/A/R 中的哪一类？请解释理由。  
    

`

它给的答案不会 100% 准确，但能帮我快速过一遍。

**整理那 500 条笔记，我并没有一次性搞完。**  
而是：

  * 用了 2–3 个晚上，把过去 1 个月常用的那一批先理顺
  * 后面每次用到一条旧笔记，就顺手判断一次「它该住在哪」



坚持一段时间后，你会发现：

> 真正经常用的那 20% 内容，  
> 已经被你搬进了一个更合理的「新公寓」。

## 四、整理完 500 条笔记之后，我最大的 3 个改变

标题里说「我的改变是……」，我就不讲宏大的，而讲 3 个非常具象的变化。

### 改变一：写东西不再从「新建空白页」开始

以前写文章、写文档、写分享稿时，我都是：

  1. 新建一个空白页
  2. 盯着闪烁的光标发呆
  3. 打开浏览器开始搜「XXX 原理」「XXX 实践」
  4. 一边看，一边怀疑自己：「我是不是太菜了？」



现在的流程变成了：

  1. 在 01_Projects 里建一个写作项目（比如这篇 PARA 文）
  2. 先打开 02_Areas/个人知识管理，看看之前的反思和想法
  3. 再打开 03_Resources/PARA_相关资料，翻我整理过的要点
  4. 最后再新建「这篇文章的项目笔记」，写大纲、写结构



**写作不再是「对着空气硬挤」，而是「在现有积木上搭」。**

我第一次感受到所谓「第二大脑」的力量就是：

> 我在写这篇文章的时候，  
> 其实是在和「过去的我」一起写——  
> 他帮我记下了很多当时的困惑、兴奋、质疑。

### 改变二：项目推进更快了，尤其是在「开始」和「收尾」阶段

过去做一个项目（比如一个需求、一个学习计划），最常出现两个问题：

  * 开始困难： 要翻各种资料、群聊记录、旧文档 不知道从哪里起手
  * 收尾困难： 事是做完了，文档散落一地 想复盘，无从下手



现在，我给每个项目在 `01_Projects` 下建一个「项目主页」：

Markdown
    
    
    # Project｜用 PARA 整理 500 条笔记  
      
    ## 1. 目标  
      
    ## 2. 任务列表  
      
    ## 3. 相关资料（链接到 Resources）  
      
    ## 4. 中途记录（碰到的坑、思路变化）  
      
    ## 5. 结果 & 复盘  
    

`

当项目完成后，我会：

  * 把这个项目文件夹整个移到 04_Archives/Projects_Completed
  * 在 02_Areas/个人知识管理 里，补上一句这次项目带来的新理解



**开始时，有「项目主页」帮我聚合一切；  
结束时，有「领域笔记」帮我抽象升一级。**

这种「项目 → 领域」的回流，以前是做不到的。

### 改变三：心里的「知识焦虑」明显少了

以前的焦虑来源很简单：

> 「我明明看了这么多东西，为什么还是没有体系？」  
> 「我好像哪都学了一点，又哪都不扎实。」

PARA 帮我做了一件很重要的事：

  * 它不要求我一下子搭出「完美知识体系」
  * 它只要求我：每一条信息，给它一个「当前最合理的住址」



久而久之，你会发现：

  * 自己负责的领域（Areas）慢慢有了「主线」
  * 每次新看的资源（Resources），都有机会挂在某根主线上
  * 某天你回顾某个领域，会看到一个渐渐长出来的结构



那种感觉，像是：

> 以前我总觉得大脑是一团乱麻，  
> 现在我知道，有几根主线是稳的，乱的是那些暂时还没整理的线头。

焦虑没有 100% 消失，但**变得可被定位和处理** 了。

## 五、用 PARA 时，我刻意「没做」的几件事

这部分也很重要，因为很多人 PARA 用不下去，就是因为一上来做得太多。

### 5.1 我没有去追求「完美分类」

典型强迫症问题：

  * 这条笔记既跟项目有关，又跟领域有关，怎么办？
  * 这个是「阅读笔记」还是「学习笔记」？
  * 这个算「输出」还是「资源」？



我的做法只有一句话：

> **先随便选一个最合理的，  
>  以后真的发现不合理，再挪。**

我甚至接受：

  * 某条笔记，在项目里是一个副本，在领域里又被当作一条记录
  * 某条卡片，最开始在 Resources，后来搬到了 Areas



我更关心的是：**我能不能在需要的时候找到它** ，  
而不是它是否属于理论上最完美的分类。

### 5.2 我没有给每条笔记加上复杂标签

我知道很多人玩 PARA 会搭配一堆标签系统：

  * #learning #idea #todo #article ……



我一开始也很心动，后来强制自己忍住了。

现在我的标签规则很简单：

  * 标签只用来标记「跨 PARA 维度的东西」 比如：#Obsidian、#AI、#PARA
  * 不用标签来标记「状态」 比如 #已完成、#待整理，这些用文件夹 + 前缀解决



否则，500 条笔记 × 若干标签，  
你只会多一个要维护的系统而已。

### 5.3 我没有一次性「用 PARA 重构人生」

刚接触 PARA 时，我也有过那种冲动：

> 「我要立刻把工作、生活、健康、理财、学习全部用 PARA 管起来！」

后来我给自己踩了刹车：

  * 第一阶段：只在「工作项目」和「写作项目」里用 PARA
  * 第二阶段：扩展到「学习」和「个人成长」领域
  * 直到最近，才慢慢把它用到「健康」「理财」这些生活领域



**每扩展一个领域，我会先问自己：  
“有没有一个真实项目，正在这个领域里发生？”**

有，就先从那个项目开始。  
没有，就先别急着画饼。

## 六、如果你现在也有一堆乱笔记，可以从「最小 PARA」开始

最后，给你一个可以 **今天就动手** 的「最小版本」 PARA 起步方案。

### 第一步：建 4 个顶层文件夹（或 4 个标签/数据库视图）

不管你用的是 Obsidian、Notion、Logseq 还是其他工具，  
先建这 4 个最简单的「抽屉」：

text
    
    
    P_Projects  
    A_Areas  
    R_Resources  
    A_Archives  
    

`

不用想太多，先建出来。

### 第二步：选 1 个正在进行的「项目」，给它建一个主页

比如：

  * 写一篇文章
  * 做一个需求
  * 学一门新技术



在 `P_Projects` 里给它建一个项目笔记：

Markdown
    
    
    # Project｜{项目名}  
      
    ## 1. 目标  
      
    ## 2. 任务清单  
      
    ## 3. 相关资料（可以链接到 R_Resources）  
      
    ## 4. 过程记录  
      
    ## 5. 结果 & 复盘  
    

`

接下来所有与这个项目有关的：

  * 需求讨论
  * 笔记草稿
  * 链接收集



都尽量往这里靠拢。

### 第三步：选 1 个你长期关心的「领域」，给它建一个主页

比如：

  * 个人知识管理 / 第二大脑
  * 职业发展
  * 身体健康
  * 个人 IP / 写作



在 `A_Areas` 里建一条：

Markdown
    
    
    # Area｜个人知识管理  
      
    ## 1. 我现在的状态  
      
    ## 2. 为什么要在这个领域变好？  
      
    ## 3. 今年/这个季度的关注点  
      
    ## 4. 当前在做的相关项目（链接到 Projects）  
      
    ## 5. 一些关键思考 & 决定  
    

`

你会发现：

  * Projects 里，是「正在进行的动作」
  * Areas 里，是「这些动作背后更长期的方向」



### 第四步：给自己 1 个「只整理最近 30 天」的约定

你不需要像我一样一次迁 500 条。

你可以只做两件事：

  1. 以后新建的笔记，都尽量放进 P/A/R 里的某一个
  2. 每当你打开一条以前的笔记时，顺手问一句： 「未来 30 天，我会用到你吗？」 会 → 挪到 Projects 或 Areas 不确定 → Resources 几乎不会 → Archives



坚持一两周，你的「活跃笔记区」基本就清爽多了。

## 尾声：PARA 改变的不是笔记，而是我看待「信息」的方式

回头看，用 PARA 整理 500 条笔记，带给我的最大改变其实是：

> **我不再把每一条笔记，当成「知识的墓碑」。**

以前我记完一条笔记，会有一种心理：

  * 「OK，我完成了」——于是它被放进某个角落，慢慢长满灰尘



现在我更像是在做这几件事：

  * 每条笔记只是一个“正在路上的素材”
  * 它会先进 Projects，为某个具体目标服务
  * 完成后，被抽象成 Areas 里的「一个积累」
  * 再变成 Resources 里的一块砖，将来为其他项目所用



它们不是静态的，而是在一个个项目之间被**流动、重组、升级** 。

对一个写 Bug 的后端来说，这有点像：

> 以前我只会不断新增代码文件；  
> 现在我学会了重构、拆库和抽出公共模块。

如果你现在也被自己的笔记库压得有点喘不过气，  
不妨先别急着删东西或换工具。

你可以先给它四个抽屉，  
再慢慢学会问那句简单的问题：

> 「对我现在的生活和工作来说，  
> 这条笔记，是一个项目、一个领域、一块资源，还是一段历史？」

答案不会一成不变，  
但你每问一次，就会比上一次更接近你真正想要的那个「第二大脑」。

如果你愿意，也可以在评论里告诉我：

  * 你现在大概有多少条笔记？
  * 最让你头疼的问题是什么？（找不到？用不上？太碎？）

把「如何用 AI + PARA 半自动整理旧笔记」的具体过程拆出来给你看。

  


  


  


  


  
  


我是一只阿木木，一个写后端代码、也常写 Bug 的普通人。

在 AI 时代，我不想只当更快的 coder，更想像做产品一样，系统地经营自己的成长。

这里我会用「产品思维 + Obsidian + AI」搭一套个人成长与知识管理系统：

  * 把零散输入变成结构化的知识库
