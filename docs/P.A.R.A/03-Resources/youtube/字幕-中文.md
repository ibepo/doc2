## 🎬 开场白

我以前启动 Claude Code 项目的方式完全错误。我会在终端里输入 Claude，然后就开始自由式提示，没有规划、没有设置、没有构建系统。这就像在没有蓝图的情况下盖房子。最终虽然能盖出点什么，但会很混乱、低效，充满本可避免的问题。

但在过去一年用 Claude Code 构建了几十个项目后，我发现了一个简单的三部分系统，能让每个项目从第一天起就容易 10 倍。在这个视频中，我将分享我启动每个新 Claude Code 项目时使用的确切系统，帮你节省数月的挫败感和浪费时间。

我称之为 **PSB 系统**：
- **P**lan（规划）
- **S**etup（配置）
- **B**uild（构建）

## 📖 三个阶段概览

**第一阶段是规划** —— 在写一行代码之前为项目成功做准备。我们会涵盖我在构建之前问自己的两个关键问题，以及如何创建一个结合产品需求和工程设计的项目规格文档，让 Claude 能够完全按照你想要的方式构建。

**第二阶段是配置** —— 用 Claude Code 有效构建所需的一切进行配置。我们会涵盖 Claude Code 的七步设置清单，从设置 GitHub 仓库和创建 CLAUDE.md 文件，到插件、MCP 和自定义命令等高级功能。

**第三阶段是构建** —— 首先构建你的 MVP，然后是项目的其余里程碑。我们会涵盖我用于每个项目的三种开发工作流：单一功能的通用工作流、保持组织的基于 Issue 的开发，以及同时处理多个功能的多代理开发。

无论你是启动第一个 Claude Code 项目，还是每天都在使用，我保证你会从本视频中学到一些东西，帮助你用 Claude Code 更快、更聪明地构建。

# Phase 1: Plan（规划阶段）

## 📋 规划概述

我们将涵盖两个最重要的问题、如何创建一个同时捕获产品和工程需求的项目规格文档，以及如何使用 AI 在每一步帮助你进行规划。

听着，我懂。规划听起来很无聊。你想开始写代码，但请相信我。**前期花 15 分钟规划项目，会为你节省后续几小时甚至几天的挫败感。**

在打开 Claude Code 之前，我会对项目要实现的目标进行头脑风暴。具体来说，我会问自己两个问题，并用笔和纸或 Google 文档记下答案。

---

## ❓ 问题一：你实际上想做什么？项目的目标是什么？

你要明确：

- 你是想学习一项新技术吗？
- 你是想与客户验证一个想法吗？
- 你是在构建产品或功能的 alpha 版本吗？
- 你只是在原型验证，看看某事是否可行吗？

**弄清楚你实际想做什么，会改变你处理项目的一切方式。** 它告诉你什么是重要的构建，什么可以跳过。

### 举例说明：

如果你只是想**原型验证**一个功能是否是个好主意：
- 可以只关注该功能的核心功能
- 不需要担心生产级代码或边缘情况
- 可以快速行动，打破常规

但如果你要构建想要**交付给真实用户**的东西：
- 需要考虑安全性
- 需要考虑错误处理
- 需要考虑边缘情况
- 需要让产品感觉精致的所有细节

> **规划时的关键点**：你越清晰，Claude 就越能理解你想要实现的目标并相应地构建。

---

## ❓ 问题二：你想要的功能里程碑是什么？

这里你可以开始将项目分解为清晰的阶段：

- **版本一**是什么样子的？可能只关注一个核心功能。
- 你愿意**留下或留给未来版本**的是什么？
- 然后你可以将同样的思维应用到版本二、版本三等等。

对于大多数项目，我喜欢考虑 **MVP（最小可行产品）**，然后是一两个版本的改进：

- **MVP** = 验证想法或证明概念可行的绝对最小值
- **未来版本** = 添加脚手架、润色或优化

---

## 🤖 用 AI 帮助规划

一旦你有了头脑风暴，这里你可以使用 AI 帮助充实项目计划。

### 专业技巧：告诉 AI 问你问题

例如，当我开始一个新项目时，我会把头脑风暴放在一个 markdown 文件中给 Claude，然后问：

> "嘿 Claude，我想构建这个项目。为了成功构建 MVP，我需要回答的三个最重要的问题是什么？"

然后 Claude 会问关于头脑风暴的**澄清性问题**，帮助你发现没有完全想通的事情：

- 用户是谁？
- 核心问题是什么？
- 你针对什么平台？
- 有什么技术约束或偏好？
- 成功标准是什么？

**这个提问步骤帮助你及早发现盲点，产生更好的规格文档。**

---

## 📝 项目规格文档

回答完这些问题后，你可以让 Claude 帮助你起草一个**结合产品和工程的规格文档**。

### 推荐结构：

1. **概述与目标** - 项目要实现什么
2. **用户故事和场景** - 谁在使用以及如何使用
3. **需求** - 必须有的 vs 最好有的
4. **架构和数据模型** - 技术栈和结构
5. **API 和集成** - 需要连接什么
6. **非功能性需求** - 性能、安全性、可观察性
7. **MVP 的验收标准** - 如何知道完成了

> **关键点**：输出应该足够具体，让 Claude Code 可以开始构建而不需要猜测。如果你包含示例负载、模型字段和端点形状，你会得到更好的结果。

# Phase 2: Setup（配置阶段）

## 🛠️ 配置概述

这里你要用 Claude Code 有效构建所需的一切进行配置。我为 Claude Code 使用**七步设置清单**。

---

## 1️⃣ 设置 GitHub 仓库

- 为你的技术栈设置正确结构的仓库（Web 或 Mobile）
- **预先决定进行基于 Issue 的开发**
  - 为功能或 Bug 打开 Issue
  - 使用以 Issue 命名的分支

---

## 2️⃣ 创建环境变量文件

- 创建 `.env` 文件
- 记录本地开发、staging 和生产环境所需的密钥

---

## 3️⃣ 添加 CLAUDE.md 文件

在仓库中添加 `CLAUDE.md`（或 `claw.md`）文件。

**这个文件的作用**：
- 解释项目
- 说明技术栈决策
- 编码约定
- 如何运行/测试项目

它是 Claude Code 的入门文档。

---

## 4️⃣ 设置自动化项目文档

- **README** 部分：设置、脚本、故障排除
- **docs/** 文件夹：架构笔记
- 启用文档生成器或使用 Claude 在代码更改时维护文档

---

## 5️⃣ 安装插件

为你的工作流安装所需的插件，例如：
- 文件系统插件
- GitHub 插件
- 框架助手

---

## 6️⃣ 安装 MCP 服务器

为以下工具安装 MCP 服务器：
- 数据库
- HTTP 客户端
- 其他特殊功能

让 Claude 可以与你的环境交互。

---

## 7️⃣ 设置自定义斜杠命令和子代理

为常见任务设置自定义斜杠命令和子代理，例如：

| 命令 | 用途 |
|------|------|
| `/scaffold page` | 脚手架页面 |
| `/write test for module` | 为模块编写测试 |

专门代理示例：
- 前端代理
- 后端代理
- 文档代理

---

## 🔧 高级配置

我还推荐：

- **预先配置权限**：让 Claude Code 对仓库和工具有正确的访问权限，而不需要不断提示
- **添加钩子**：
  - 预提交钩子
  - CI 检查
  - 代码格式化程序

以保持质量一致。

# Phase 3: Build（构建阶段）

## 🔨 构建概述

首先直接从规格文档构建你的 MVP。我为每个项目使用**三种开发工作流**。

---

## 工作流 1：单一功能开发

适用于独立功能：

1. 选择一个功能
2. 打开一个 Issue
3. 让 Claude Code 计划步骤（要编辑的文件、要编写的测试）
4. 实现
5. 测试
6. 合并

---

## 工作流 2：基于 Issue 的开发

保持一切组织有序：

- 一切通过 Issue 组织
- 每个 Issue 描述：
  - 范围
  - 验收标准
  - 测试步骤
- Claude Code 可以：
  - 移动 Issue 状态
  - 打开 PR

---

## 工作流 3：多代理开发（Multi-Clauding）

并行处理多个功能：

- 运行多个 Claude 实例
- 或使用 Git worktrees
- 让不同代理可以并行处理单独的功能
- 而不会互相踩到更改

---

## 💡 高效构建的建议

| 建议 | 说明 |
|------|------|
| **保持规格更新** | 随着学习更新规格文档 |
| **先写测试** | 或至少与功能同步编写，让 Claude Code 有清晰的验证 |
| **分块工作** | 将工作分成小的、可审查的步骤 |
| **添加日志和监控** | 即使在 MVP 中也使用，以及早发现问题 |
| **定期重构** | 用 Claude 的帮助进行重构，以减少技术债 |
